# Lab 07 - Reserva DHCP e persistência do endereço IP

## Visão geral

Este laboratório documenta a configuração de uma reserva DHCP para o servidor Debian na rede local.

Originalmente, o servidor utilizava o endereço IP `192.168.1.117`, mas, após permanecer desligado por um período prolongado, recebeu um endereço diferente do servidor DHCP: `192.168.1.116`.

Como o servidor é utilizado para serviços de rede, monitoramento, Apache, Zabbix e administração remota, manter um endereço IP previsível é importante.

Em vez de forçar uma configuração de IP estático diretamente no Debian, uma reserva DHCP foi configurada no roteador. Isso permite que o Debian continue utilizando DHCP enquanto o roteador atribui consistentemente o mesmo endereço ao servidor.

---

## Objetivos

* Compreender a diferença entre DHCP e configuração de IP estático.
* Investigar por que o servidor mudou de `192.168.1.117` para `192.168.1.116`.
* Identificar a configuração de rede utilizada pelo Debian naquele momento.
* Verificar a concessão DHCP e as informações de roteamento.
* Testar conceitos de configuração de IP estático.
* Recuperar a conexão de rede após alterações de configuração.
* Configurar uma reserva DHCP no roteador.
* Manter o servidor Debian utilizando DHCP com um endereço IP previsível.

---

## Ambiente

| Item | Informação |
| --- | --- |
| Sistema operacional | Debian 13 |
| Interface de rede | `wlan0` |
| Rede | `192.168.1.0/24` |
| Gateway | `192.168.1.1` |
| IP anterior | `192.168.1.117` |
| IP atribuído por DHCP | `192.168.1.116` |
| IP reservado | `192.168.1.117` |
| Cliente DHCP | `dhcpcd` |
| Roteador | Zyxel PX3321-T1 AX3000 Wi-Fi 6 GPON VoIP Gateway |

---

## O problema

O servidor Debian utilizava anteriormente:

```text
192.168.1.117
```

Após permanecer desligado por aproximadamente um dia e ser ligado novamente, o servidor DHCP atribuiu:

```text
192.168.1.116
```

A interface mostrou o novo endereço como dinâmico.

A tabela de roteamento também confirmou que o servidor utilizava `192.168.1.116` como endereço de origem atribuído por DHCP:

```text
default via 192.168.1.1 dev wlan0 proto dhcp src 192.168.1.116
192.168.1.0/24 dev wlan0 proto dhcp scope link src 192.168.1.116
```

Isso demonstrou que o servidor não estava configurado para manter permanentemente `192.168.1.117`.

---

## Investigação da configuração de rede

A interface de rede foi inspecionada com:

```bash
ip addr show wlan0
```

Inicialmente, a interface mostrou:

```text
inet 192.168.1.116/24
```

O arquivo de configuração de rede também foi verificado:

```bash
cat /etc/network/interfaces
```

A configuração original utilizava DHCP:

```text
allow-hotplug wlan0
iface wlan0 inet dhcp
    wpa-ssid Familia_Silva
    wpa-psk SUA_SENHA
```

Portanto, esperava-se que o servidor obtivesse seu endereço IPv4 dinamicamente.

---

## Identificação do cliente DHCP

Os processos em execução foram verificados para identificar qual serviço gerenciava o DHCP:

```bash
ps aux | grep dhcpcd
```

A saída mostrou que `dhcpcd` estava em execução.

O pacote instalado também foi verificado:

```bash
dpkg -l | grep dhcpcd
```

O sistema utilizava:

```text
dhcpcd-base
```

A configuração DNS também continha evidências de que `dhcpcd` gerenciava a concessão de rede:

```text
# Generated by dhcpcd from wlan0.dhcp, wlan0.dhcp6, wlan0.ra
```

Isso foi importante porque explicou por que alterar manualmente o endereço não removia permanentemente o endereço atribuído por DHCP.

---

## Teste de configuração de IP estático

Para compreender o comportamento, a configuração de rede foi temporariamente alterada de DHCP para endereçamento estático.

A configuração foi alterada para utilizar:

```text
iface wlan0 inet static
    address 192.168.1.117
    netmask 255.255.255.0
    gateway 192.168.1.1
```

A configuração foi verificada com:

```bash
ifquery wlan0
```

O comando informou corretamente a configuração estática.

Entretanto, a interface ativa não refletiu imediatamente a configuração esperada porque outro processo DHCP ainda gerenciava a interface.

---

## Conflito entre DHCP e configuração estática

Após reativar a interface, o servidor apresentou temporariamente dois endereços IPv4:

```text
inet 192.168.1.117/24
inet 192.168.1.116/24 ... dynamic
```

Isso demonstrou que a configuração estática em `/etc/network/interfaces` não era a única configuração que afetava a interface.

O cliente DHCP ainda conseguia manter o endereço atribuído dinamicamente.

Foram realizadas tentativas de remover manualmente o endereço dinâmico:

```bash
sudo ip addr del 192.168.1.116/24 dev wlan0
```

Entretanto, o cliente DHCP podia recriar o endereço.

Isso mostrou por que manipular manualmente a interface não era uma solução permanente apropriada.

---

## Recuperação da rede

Durante a investigação, a interface foi temporariamente desativada durante o teste da configuração.

Isso interrompeu a conexão SSH com o servidor.

A interface foi restaurada com:

```bash
sudo ifup wlan0
```

A conectividade foi então verificada novamente pela rede.

Essa foi uma lição prática importante: alterações de configuração de rede realizadas por SSH podem encerrar imediatamente a sessão remota quando a interface ativa é modificada.

---

## Reserva DHCP

Em vez de continuar tentando contornar o cliente DHCP no Debian, a configuração foi alterada no ponto adequado da arquitetura de rede: o servidor DHCP.

O roteador Zyxel disponibiliza uma tabela de reservas DHCP.

O endereço MAC do servidor foi identificado como:

```text
xx:xx:xx:xx:xx:xx
```

Uma reserva foi criada no roteador:

| Parâmetro | Valor |
| --- | --- |
| Endereço MAC | `xx:xx:xx:xx:xx:xx` |
| IP reservado | `192.168.1.117` |

O roteador foi configurado para associar esse endereço MAC a `192.168.1.117`.

---

## Por que utilizar reserva DHCP?

Uma reserva DHCP oferece vantagens das duas abordagens:

### O Debian continua utilizando DHCP

O servidor não precisa definir manualmente:

```text
address
netmask
gateway
```

O roteador fornece essas informações por DHCP.

### O servidor recebe um endereço previsível

O roteador associa o endereço MAC do servidor a:

```text
192.168.1.117
```

Assim, os serviços configurados em torno desse endereço podem continuar utilizando o mesmo endpoint.

### Gerenciamento centralizado da rede

A atribuição de IP é controlada pelo roteador em vez de configurada manualmente no servidor.

Isso é particularmente útil em ambientes com vários servidores e dispositivos de rede.

---

## Projeto final de rede

A configuração final pretendida é:

```text
                    Local Network
                         |
                  192.168.1.0/24
                         |
                Zyxel Router
                  192.168.1.1
                         |
                 DHCP Reservation
                         |
              MAC: xx:xx:xx:xx:xx:xx
                         |
                  192.168.1.117
                         |
                   Debian Server
                       wlan0
                         |
              Zabbix / Apache / SSH
```

O servidor Debian permanece como cliente DHCP.

O roteador é responsável pela atribuição esperada de `192.168.1.117` ao servidor.

## Validação

A configuração de rede pode ser verificada com:

```bash
ip addr show wlan0
```

O endereço esperado é:

```text
192.168.1.117/24
```

A tabela de roteamento pode ser verificada com:

```bash
ip route
```

A rota padrão esperada é:

```text
default via 192.168.1.1
```

A conectividade com o roteador pode ser testada com:

```bash
ping -c 4 192.168.1.1
```

A conectividade com a Internet pode ser testada com:

```bash
ping -c 4 8.8.8.8
```

A resolução DNS pode ser testada com:

```bash
ping -c 4 google.com
```

O acesso SSH pode então continuar utilizando:

```bash
ssh usuario@192.168.1.117
```

---

## Conceito de configuração final

A configuração desejada do Debian é DHCP:

```text
allow-hotplug wlan0
iface wlan0 inet dhcp
    wpa-ssid Familia_Silva
    wpa-psk SUA_SENHA
```

O ponto importante é que a persistência do IP é gerenciada pelo roteador, em vez de forçar um endereço estático no Debian.

A senha real do Wi-Fi foi intencionalmente omitida desta documentação.

---

## O que aprendi

* Endereços DHCP não são necessariamente permanentes.
* Um servidor pode receber um IP diferente após um longo período offline.
* `ip addr` pode indicar se um endereço é dinâmico.
* `ip route` pode revelar o endereço de origem atribuído por DHCP e o gateway padrão.
* `dhcpcd` pode continuar gerenciando uma interface mesmo quando outra configuração de rede parece definir um endereço estático.
* Alterar a configuração de rede remotamente por SSH pode desconectar a sessão.
* Remover manualmente um endereço DHCP não é uma solução permanente.
* A reserva DHCP é uma forma prática de manter endereços previsíveis.
* A reserva DHCP deve ser configurada no dispositivo que atua como servidor DHCP.
* Manter o servidor com DHCP enquanto seu endereço é reservado no roteador oferece gerenciamento centralizado da rede.
* O endereçamento IP estável é importante para serviços de infraestrutura, como Zabbix, Apache, SSH e outras aplicações de servidor.

---

## Resultado

O problema de persistência do endereço IP foi identificado e resolvido por meio de uma reserva DHCP no roteador Zyxel.

O servidor Debian pode continuar utilizando DHCP enquanto o roteador reserva:

```text
192.168.1.117
```

para sua interface de rede:

```text
xx:xx:xx:xx:xx:xx
```

Isso fornece um endereço previsível sem exigir a configuração manual de um IP estático no Debian.
